Historyjki służą do dopisywania kolejnych zadań dla agenta AI.
Przy każdej historyjce powininen być dopisek czy została wykonana, czy czeka na wykonanie lub informacja że należy ją właśnie wykonać.
Wykonane historyjki należy również dopisywać do dziennika iteracji.

1. Porządek w kodzie - zakończono pozytywnie
Aktualnie projekt jest napisany w bardzo chaotyczny sposób.
Pliki style.css i script.js zawierają dużo nadmiarowego kodu, który wyniknął z niezrozumienia wymagań projektu.
Również plik index.html jest napisany niedbale.
Zadaniem jest posprzątanie kodu, uporządkowanie w logicznej kolejności, napisanie odpowiednich komentarzy w kodzie i czekanie na wyniki manualnych testów, które powinny sprawić że aplikacja działa nie gorzej niż wcześniej.
Celem tego zadania jest również wygenerowanie dodatkowego raportu, w którym agent AI opisze jak rozumie działanie Edytora Tabel, rozpisze jego mocne i słabe strony, co należy poprawić i zmienić, jaką widzi drogę do osiągnięcia MVP i co mogłoby być rozwijane po MVP.
Ważne jest również aby przeczytać "Generate CSS - output class" przed wykonaniem prac nad kodem.

WYKONANE W ITERACJI 01:
- Przepisano i uporządkowano css/style.css z szczegółowymi komentarzami
- Przepisano i uporządkowano js/script.js z komentarzami JSDoc
- Uporządkowano index.html z komentarzami HTML
- Dodano wsparcie dla <tfoot> w całym projekcie
- Wypełniono domyślne wartości neutralne w kontrolkach
- Stworzono raport Iteracja_01_Raport.md w folderze documentation/Reports/

2. Brak neutralnych wartości w wygenerowanym CSS - zakończono pozytywnie (efekty zmian widoczne w pliku Generate CSS - output class)
**Problem:** Funkcja `css()` w `getTableCSS()` pomija puste wartości. Jeśli użytkownik nie ustawi np. border, to w wygenerowanym CSS nie będzie `border: none;`. To oznacza, że po wklejeniu do projektu użytkownika, jego style mogą przeciążyć nasz CSS.

**Rozwiązanie:** Zawsze generować pełny CSS z neutralnymi wartościami, nawet jeśli użytkownik ich nie zmienił.

WYKONANE W ITERACJI 02:
- Zmodyfikowano funkcję css() aby przyjmowała trzeci parametr defaultVal
- Zaktualizowano getTableCSS() aby wszystkie właściwości miały domyślne wartości neutralne
- Wartości neutralne: transparent, inherit, none, 0, 100%, collapse, sans-serif, 16px, 1.4, #000000, 0px, 6px 8px
- Stworzono raport Iteracja_02_Raport.md w folderze documentation/Reports/

3. Niewygodne inputy typu text dla złożonych wartości - zakończono pozytywnie
**Problem:** Użytkownik musi ręcznie wpisywać wartości jak `1px solid black` dla borderów. To wymaga znajomości CSS i jest podatne na błędy.

**Rozwiązanie:** Zastąpić pola tekstowe bardziej przyjaznymi kontrolkami (assumptions.txt punkt 16):
- Border: osobny input dla width (range), style (dropdown), color (color picker)
- Margin/Padding: oddzielne kontrolki dla każdej strony lub skrót
- Font-family: dropdown z popularnymi czcionkami

WYKONANE W ITERACJI 03:
- Zamieniono wszystkie kontrolki border na kompozytowe kontrolki (range dla width, select dla style, color picker dla koloru)
- Zamieniono kontrolkę margin na 4 osobne range inputy (top, right, bottom, left)
- Zamieniono kontrolkę font-family na dropdown z popularnymi czcionkami
- Zamieniono kontrolkę border-collapse na dropdown (collapse/separate)
- Zaktualizowano funkcję createControl() aby obsługiwała nowe typy kontrolek
- Dodano funkcje parseBorderValue() i parseMarginValue() do parsowania wartości przy Load CSS
- Zaktualizowano funkcję updateInputs() aby prawidłowo wypełniała nowe kontrolki
- Dodano style CSS dla nowych kontrolek (et-control-border, et-control-margin)
- Dotyczy: Table Border, Header Border, Footer Border, Cell Border, Row Border, Table Margin

4. Brak możliwości włączania/wyłączania header i footer - czeka na wykonanie
**Problem:** Assumptions.txt punkt 5 wymaga możliwości włączenia/wyłączenia header i footer. Obecnie nie ma takiej kontrolki.

**Rozwiązanie:** Dodać checkboxy "Show header" i "Show footer" które pokazują/ukrywają odpowiednie sekcje tabeli i kontrolki.

5. Ograniczone wsparcie dla inherit i transparent w Load CSS - czeka na wykonanie
**Problem:** Wartości `inherit` i `transparent` są traktowane jak puste stringi w parsowaniu.

**Rozwiązanie:** Poprawić logikę parsowania, aby rozróżniała brak wartości od wartości neutralnych.

6. Brak walidacji wprowadzanych wartości - czeka na wykonanie
**Problem:** Użytkownik może wpisać nieprawidłowe wartości CSS (np. "abc" jako font-size), co spowoduje błędy w CSS.

**Rozwiązanie:** Dodać walidację inputów i komunikaty o błędach.
